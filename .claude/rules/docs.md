# Docs

Applies to every Markdown file: `ROADMAP.md`, `CLAUDE.md`, rules and skills.

- Say what is true now. No diary of what was built, tried or found when; git keeps that.
- Edit in place. Never append a dated note; delete what is wrong or no longer matters.
- Track work as a tick list, one line per item: `- [x]` done, `- [ ]` left. A roadmap phase is a one-line gate and its items.
- One fact in one place. Point to the rule that holds it instead of repeating it.
- Short, flat sentences. No openers, summaries or closers, no "not X but Y", no triads, no em dashes, no bold lead-ins, no sales words.
- Use real names in backticks: packets, classes, config keys, files. Never coin one.
- Tag a fact checked against BDS with its version, as in "(1.26.60)".
- A table only for data with columns; a list otherwise.
